- 相对于 [AVL Tree](/data-structures-algorithms/ads/avl-tree/)，是另一种平衡二叉搜索树
	- 对“平衡”的定义和策略不太一样
# 染色
- 红黑树引入了红色和黑色两种颜色，给每个结点多打一个标记
## 规则
- **左根右，根叶黑，不红红，黑路同**
- 根和叶子（NULL）都是黑色
	- 画出空结点有助于判断树是不是红黑树
- ~={red}红色=~结点的左右孩子都是黑色
	- 也就是说不存在连续的两个~={red}红色=~节点
- 任一结点到叶子的所有路径上黑色结点数量相同
# 插入
- 插入结点默认为~={red}红色=~
	- 若非根新结点设置为黑色，其所在路径**必然违反**黑路同，这会使得后续调整比较麻烦
	- 而若设置为~={red}红色=~，**有可能**不破坏红黑树的任何性质，总的来说代价更小
## 插入调整
- 若插入破坏了性质，则需进行调整
1. 插入结点是根结点 —> 直接变黑
2. 插入结点的叔叔是红色 —> 叔、父变黑，爷变红，再把爷作为当前结点继续检查
	- 可能~={yellow}不止调整一轮=~
3. 插入结点的叔叔是黑色 —> （LL, RR, LR, RL）旋转，然后变色
	- 黑色也包括 NULL
# 删除
- 这个相当复杂！
## 二叉搜索树的删除
- 根据删除结点的性质：
	1. 没有孩子——~={yellow}直接删除=~
	2. 只有左/右子树——~={yellow}用该孩子直接代替=~
	3. 左右子树都有——~={yellow}找到它的直接后继（或前驱）代替，然后递归=~
- 总之，第三种情况最后一定会转化成前两种情况之一
	- 对于红黑树也是这样
## 红黑树的删除
- 红黑树的删除其实操作本身其实就是二叉搜索树的操作，但对于删除后破坏红黑树性质的情况，需要作一些调整
### 双黑
双黑是红黑树删除里的一个记账概念。实际删除黑色结点后，把少掉的一重黑记在替代结点（可能是 NULL）上，称为双黑；它不是预先标在待删除结点上的真实颜色。
### 1. 删除的结点没有孩子
#### ① 若删除的是~={red}红色=~结点
- 直接删除即可
#### ② 若删除的是黑色结点
- 若它是唯一的根结点，直接删除即可；否则会破坏黑路同
- 关注它的兄弟结点：
	- 下文用 $p$ 表示父结点，$s$ 表示兄弟结点，$r$ 表示参与调整的红色侄子
	1. 兄弟是黑色
		1. 兄弟至少有一个~={red}红色=~孩子：（LL, RR, LR, RL）变色 + 旋转
			- 有两个~={red}红色=~孩子的情况算作 LL（RR 同理）
				- r 变 s，s 变 p，p 变黑
				- ~={yellow}对结点 p =~右旋
				- 双黑变单黑
			- RR 和 LL 是对称的
				- r 变 s，s 变 p，p 变黑
				- 左旋
				- 双黑变单黑
			- LR
				- r 变 p，p 变黑
				- 左旋左孩子，然后右旋
				- 双黑变单黑
			- RL 与 LR 镜像
		2. 兄弟的孩子都是黑色：兄弟变~={red}红=~，双黑上移
			- 如果上移后是黑色结点，按照递归理解
			- 如果上移后是~={red}红色=~结点，直接将其变成单黑即可
			- 遇到根结点也直接变成单黑
	2. 兄弟是~={red}红色=~：兄父变色；双黑在左则对 p 左旋，反之对 p 右旋；保持双黑继续调整
### 2. 删除的结点只有左/右孩子
- 红黑树由于自身性质，对于上述的情况 2，只可能为黑色结点有左/右~={red}红色=~孩子，且这个孩子不再有其他孩子（不考虑 NULL）
- 代替后变黑

# 性质
## 路径长
- 最长路径不超过最短路径的 2 倍
	- 达到上界的极端情况下，最长路径可以是黑~={red}红=~黑~={red}红=~黑……
- 含有 $n$ 个内部结点的红黑树高度满足 $h\le 2\log_2(n+1)$
- 与 AVL 树对比可知，~={cyan}后者=~对于平衡的要求更加严格（高度差绝对值 ≤ 1）
	- 红黑树的高度上界更宽松，因此查询的最坏常数可能略大
	- 对应地，红黑树插入和删除通常需要更少的旋转，但重新着色和向上检查仍可能达到 $O(\log n)$
	- （不过时间复杂度自然都是一样的）
- 实际应用中，红黑树的应用更加广泛
## 性质的破坏
- 插入操作更容易破坏不红红
- 删除操作更容易破坏黑路同
